# 一项成果整节：前后一致、术语锁、对应链

## 核心原则

**一项研究成果的四个 `\subsection` 是同一条论证，不是四篇可以各说各话的短文。** 读者从研究动机读到本节小结，遇到的任务名、难点现象、机制作用词、模块名必须是同一套；该项成果须能经**方法机制**追溯到章引言的难点，难点须能追溯到章引言的现实需求。

对应不是贴标签。“本节回应挑战一”写在动机里，不等于真的对应上了。要对上，必须先读懂该方法实际做了什么：输入是什么、关键变换卡住了哪一环、损失在惩罚什么、实验验证的是不是同一环。

### 六条铁律

1. **先建表，再动笔。** 改任一小节之前，先写出术语表与对应说明（内部草稿，不写入 `.tex`）。表建不成，说明还没读懂方法或章引言，不要开始改句子。
2. **四小节名词同一套。** 同一概念只用一个中文名；英文全称、简称、符号首次落地后不再换一套叫法。近义替换视为漂移，须改回锁定词。
3. **对应靠方法机制，不靠挑战编号。** 正文不写“回应章引言第 N 个挑战”“对应难点一”。用与章引言相同的现象词和根因词，让读者自己对上。机制对不上，再流畅也算失败。
4. **同章若干项成果共同覆盖两点难点；两点难点从现实需求长出。** 单节须写清本项在若干项中的位置：主回应哪一难点、是否为后一项铺路、不得把另一项的关键机制写成自己的贡献。
5. **模块收束、实验结论、小结问题层，落到对应链的同一机制词。** 动机说“隔离【某噪声】”，方法收束就不能改口成“提升表征质量”，实验结论也不能改口成“验证了有效性”。
6. **不一致先改术语与对应，再去 AI 腔。** 润色不得把已锁定的术语换成更“顺口”的近义词。

## 改前必做：两张表

读章引言（`\section{引言}`）与本工作节全文（至少动机合段 + 方法总体框架 + 实验主表结论句 + 本节小结），填完下两表再改。只改单槽时也要填，对照未改的三槽。

### 表 A：术语锁

| 锁定词（正文只用这一词） | 英文 / 符号 / 简称 | 允许出现的位置 | 禁用近义替换 |
|--------------------------|--------------------|----------------|--------------|
| （任务名） |  | 动机起段、小结问题层 | 不要中途改成另一套任务叫法 |
| （章引言术语，`\emph{}`） |  | 动机任务句、方法收束、小结 | 不要换成近义 |
| （难点现象词，章引言 `\textit{}`） |  | 动机合段实验句、小结问题层 | 不要改成另一套难点名 |
| （本方法模块名） | 与 `\subsubsection` 标题一致 | 合段首先/其次、方法、消融标签 | 不要合段与方法各起一套模块名 |
| （机制作用词） | 与合段“通过这种方式”一致 | 方法收束、实验结论、小结效果宾语 | 不要收束改口成“提升质量” |

**锁定规则：**

- **以章引言为上游。** 章引言已定义的术语、难点名、若干项工作的方法名与核心机制词，本工作节不得另起一套。
- **以合段为本节内上游。** 方法名的中英文全称与简称在动机合段正式登场；模块作用词以合段“首先 / 其次 / 最后”为准。
- **符号与中文同锁。** 一旦对应某组符号，后文不要把符号改口成另一套叫法却不再提锁定中文。
- **中英只落地一次。** 复合英文范式名先中文后括英文；后文用中文。方法简称在合段给出后，方法、实验、小结不重释全称。
- **小结用中文收束。** 小结把英文范式名换回已解释的中文，但必须是术语表里的那一个中文。

同一节里搜近义词，命中则改回锁定词，或在术语表里明确“二者不是同一概念”并分槽使用。

### 表 B：对应说明（内部草稿，禁止写入正文）

用 6 句说清，每句都能在方法或章引言里找到依据：

1. **现实需求。** 本章要让谁做成什么事（抄章引言需求句的对象与任务，不抄空话）。
2. **需求何以变难。** 两点难点各自的机制根因（先现象后根因，不用难点编号当主语）。
3. **本方法实际做了什么。** 输入、关键变换、损失/约束、刻意不做什么（读总体框架与各模块公式，不要只读方法名）。
4. **卡住了难点的哪一环。** 若去掉该变换，章引言里哪句现象会继续成立。
5. **如何回到现实需求。** 这一卡住使现实任务的哪一步变得可做。
6. **哪组实验证明这一卡住。** 主表趋势或哪一组消融/范式对比；结论句的宾语必须是第 4 句的机制词。

第 3 句写不出关键变换，说明还没读懂方法，停止改写，先读方法设计与源论文核心模块。

## 对应链：现实需求 ← 难点 ← 本项方法

```text
章引言现实需求（要做成的事、场景中的对象）
    ↑ 该需求在机制上何以做不成
章引言两点难点（现象 + 根因）
    ↑ 本方法的变换卡住了根因的哪一环
本项成果（模块 / 损失 / 推理期行为）
    ↑ 实验验证的是同一环
主表趋势 + 消融 / 范式对比
```

### 为何必须深入理解方法

难点名和工作名对得上，机制仍可能对不上。把工具名四个字写进动机，并不等于回应了该柱难点：若方法实际没有做卡住根因的那一变换，对应就是假的。

读方法时按下面五个问题抽**机制卡片**（内部，不写入正文）：

| 问 | 要得到的答案 | 不要停在 |
|----|--------------|----------|
| 输入是什么 | 具体对象与张量/集合 | “多模态信息”“图数据” |
| 关键变换是什么 | 实际做了哪一步、刻意不做什么 | 模块标题、方法简称 |
| 损失在惩罚/鼓励什么 | 具体互信息、对比位置、约束 | “联合训练”“对比学习” |
| 刻意不做什么 | 不走哪条既有范式、哪项不进损失 | 省略 |
| 若无此变换，章引言哪句仍成立 | 抄章引言现象句 | “性能会下降” |

机制卡片能填完，对应才允许写进各槽。填不全时，先补读方法，不要用难点名硬套。

### 合法对应格局（2 难点 × 若干工作）

对应**不必一项对一个难点**。章引言固定两点难点、若干项工作，合法格局如下。

| 格局 | 何时用 |
|------|--------|
| 两项回应同一难点的不同机制层 | 前一项给格式/可解性，后一项给解释或推广 |
| 一项回应难点一，后两项沿主线加深难点二 | 先把任务做成，再解决“做成之后仍会偏” |
| 一项回应难点一，一项换范式回应难点二，一项把同一逻辑外推到另一对象 | 对象从一类事实转到另一类 |
| 一项为后一项铺路，本身也独立回应 | 章首工作给范式，后文才谈压缩与干预 |

**禁止的对应：**

- 只把方法名写在难点名旁边，不说明卡住了哪一环。
- 若干项工作机制互相侵占：后一项的关键变换出现在前一项的合段“首先 / 其次 / 最后”里。
- 现实需求的例子映射不到各条路线。
- 难点说 A，本节全程改口 B，且未说明二者是否同一现象。
- 用“本节回应挑战一”代替机制叙述。

### 各槽如何把对应写进正文

不写编号，把机制卡片里的词写进该槽该写的位置。

| 槽 | 对应写在哪 | 写法 | 忌 |
|----|------------|------|----|
| 研究动机 · 起段任务 | “因此，本节……”的用途与落脚 | 用途接到现实需求的对象；落脚用“以缓解……”或“为……奠定基础” | 停在评估协议；落脚另起一套难点名 |
| 研究动机 · 承段不足 | 每条不足的“导致什么” | 导致的后果须是难点根因在既有方法上的实例 | 只批评论文、不接到章里为何难 |
| 研究动机 · 合段 | “首先 / 其次 / 最后”+“通过这种方式” | 每点是方法变换；收束机制词 = 术语表机制作用词 | 抄章引言工作句；写“回应了两类问题” |
| 方法设计 · 模块收束 | “通过这种方式 / 该模块利用……” | 宾语 = 本模块卡住的那一环（与合段同词） | “奠定基础”“是……的关键” |
| 实验分析 · 主表归因 | 趋势为何在某设定上更大 | 用机制卡片解释，现象与现实需求或难点一致 | “方法更鲁棒”“优势明显” |
| 实验分析 · 消融结论 | 降幅最大的变体说明什么 | 去掉的正是卡住难点的那一变换 | “该模块有效”；不指向动机判断 |
| 本节小结 · 问题层 | 困难 + 后果 | 浓缩章难点在本任务上的实例 | 复述章引言原文；只写机制不写后果 |
| 本节小结 · 效果层 | “说明了……的有效性” | 宾语 = 术语表机制作用词 | “验证了本方法的有效性” |

**非首节**承段末句用“使 / 造成 / 导致……难以……”落在后果上，仍不引用挑战编号。

## 四小节前后一致（数据流核对）

四块都改完，或只改一槽但对照其余三槽，按下表核对。任一格对不上，先改，再去 AI 腔。

| 核对项 | 动机 | 方法 | 实验 | 小结 |
|--------|------|------|------|------|
| 方法名 | 合段中英文全称 + 简称 | 用简称，不重释 | 用简称 | 至少一次；不重释全称 |
| 不足条数 | 承段 2–3 条 | 模块能落到这些点 | 至少一组消融验证其中一条 | 问题层浓缩同一组不足 |
| 机制作用词 | 合段“通过这种方式” | 各模块收束宾语 | 主表归因 + 消融结论宾语 | 效果层“说明了……”的宾语 |
| 数字 | 合段 1–2 个 ⊂ 主表 | 不报准确率 | 主表为源 | 2–3 个代表数字 ⊂ 主表 |
| 对应链 | 任务用途 ← 需求；不足后果 ← 难点根因；合段变换卡住该根因 | 模块设计理由 = 卡住该根因的步骤 | 验证的是该卡住 | 问题层 = 难点在本任务上的后果 |
| 术语 | 合段锁定 | 与合段、章引言同一套 | 消融标签与模块名同一套 | 英文换中文时仍用锁定词 |
| 槽边界 | 无公式、无模块流程 | 无下游准确率 | 不把小结写成成绩单 | 无公式、无消融 |
| 本项位置 | 不写另一项的关键变换 | 不把后文方法的模块提前实现 | 不把另一项的消融结论安在本项 | 不把同章其他工作的贡献收进本项 |

只改单槽时：打开另外三槽与章引言，按本表扫与当前槽相交的行。

## 与章级插槽的接口

| 章级已给定 | 本节如何用 | 本节不得做 |
|------------|------------|------------|
| 现实需求例子与对象 | 起段用途、小结问题层后果与之同族 | 另编一套应用故事 |
| `\textit{难点名}` + 现象根因 | 承段后果、合段机制、小结问题层用同一现象词 | 改难点名；显式写“挑战一” |
| 首先 / 其次 / 最后各项工作各一句 | 确认本项那一句的机制与本节合段、方法模块一致 | 把另外各项的机制写进本项合段 |
| 预备知识中的通式与术语 | 方法段“沿用预备知识……” | 另造与预备知识冲突的符号含义 |
| 本章小结将用的中文方法名与量化 | 数字与主表同源，中文名与术语表一致 | 本节小结抢写全章各项 |

写完本节后，若发现与章引言工作句机制不一致：优先改本节合段与方法收束使之符合真实方法；若是章引言写错了本项机制，**提醒用户**改章引言，本文件仍不直接改 `\section{引言}`。

## 定稿时的内部对照（不写入正文）

撰写时对照此粒度自检，不要把本段抄进 `.tex`。从当前稿填：

- **现实需求：** 本章要判定 / 完成什么。
- **难点根因：** 章引言该点的现象 + 机制原因。
- **方法实际做的：** 输入 → 关键变换 → 损失 → 刻意不做什么。
- **卡住哪一环：** 没有该变换，章引言哪句仍成立。
- **回到需求：** 现实任务的哪一步变得可做。
- **哪组实验证明：** 范式对比 / 组件消融 / 主表趋势。
- **在若干项中的位置：** 主回应哪一难点、是否铺路、不侵占哪一项。

## 常见问题

### Q：只改研究动机，要不要做对应链？

**要。** 至少读章引言 + 方法总体框架 + 现有合段，填完两张表再改。

### Q：对应要不要在正文里写“本节回应难点一”？

**不要。** 用与章引言相同的现象词和根因词，把方法变换写清楚。

### Q：还没读公式，能不能先按章引言工作句来写动机？

**不能把章引言那一句当方法理解。** 必须读本节省体框架与各模块。章引言句用来核对“本项位置”。

### Q：两点难点、三项工作，如何避免生硬拆成 1+1+1？

**按方法真实分工选格局。** 先填若干张机制卡片，看关键变换落在哪条根因上，再写本项。

### Q：术语锁和去 AI 腔冲突怎么办？

**术语锁优先。** 同一机制作用词在合段、收束、结论、小结重复出现，是对应链，不是 AI 腔。

### Q：发现章引言难点名与方法机制对不上，改哪边？

**先确认方法事实。** 机制以源论文与方法节为准。若章引言概括错了本项，提醒用户改章引言。本文件不直接改 `\section{引言}`。
