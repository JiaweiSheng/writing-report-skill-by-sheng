# 一项研究成果的完整撰写 / 润色

## 核心原则

**一项研究成果 = 工作章里的一个 `\section`，含四个 `\subsection`：研究动机 → 方法设计 → 实验分析 → 本节小结。** 点名方法名或节标题后，先按 [consistency.md](consistency.md) 锁定术语并写对应说明，再按数据流顺序改这四块，做跨槽核对与一次去 AI 腔。不要改章引言、预备知识、本章小结，也不要一次只改一个 subsection 就宣布整节完成。

四小节必须前后一致：同一套名词，同一条“现实需求 ← 难点 ← 本项方法”对应链。对应靠读懂方法的关键变换，不靠贴挑战编号。

### 七条铁律

1. **先定位再动笔。** 用方法名、`\label{sec:...}` 或节标题找到唯一 `\section`。四块范围以 `\subsection{研究动机}` 起到下一个 `\section` 之前。找不到或对上多个，先问用户，不要猜。
2. **先填术语表与对应说明，再改句子。** 读章引言与本节省体框架，按 `consistency.md` 填表 A、表 B 与机制卡片。写不出“关键变换 / 刻意不做什么 / 若无此变换章引言哪句仍成立”，不要开始改动机。
3. **按序、按槽读 skill。** 改动机只读 `1-motivation.md`；改方法只读 `2-method.md`；改实验只读 `3-experiment.md`；改小结只读 `4-summary.md`。`consistency.md` 全程在场。上一槽改完再读下一份。
4. **各槽守各槽边界。** 动机不写公式与流程；方法不报下游准确率；实验不把小结写成成绩单；小结不重推模块、不提消融。
5. **跨槽名词、机制作用词、数字必须一套。** 合段 1–2 个数、主表、小结代表数字同源；方法名在合段正式登场，后文用简称；合段“通过这种方式”、模块收束、实验结论、小结效果宾语用同一机制作用词。近义替换视为漂移。
6. **整节只过一遍润色。** 四小节都改完、跨槽核对通过后才读 `polish/academic-zh.md`。润色不得改锁定术语。不要每改一个 subsection 就重读一遍润色全文。
7. **行文遵守入口通则。**

## 定位

| 用户怎么说 | 怎么找 |
|------------|--------|
| 方法名 / 简称 | 在工作章 `.tex` 搜该名或 `\label{sec:...}` |
| 节标题 / 第 X.Y 节 | 对应该章 `.tex` 的 `\section{...}` |
| “当前这一节 / 光标所在工作” | 取光标所在 `\section`，须确认不是引言、预备知识、本章小结 |
| 只说“润色”且光标在某一 `\subsection` | **不要走本文件**，按入口表只改那一小节 |

工作章里不是研究成果的块：`\section{引言}`、`\section{预备知识}`、`\section{本章小结}`。点名这些时回到入口另派。

改前先列出四块起止行号，再动手。动手前先读本章 `\section{引言}`，取出：现实需求对象、两点难点的现象与根因、若干项工作中本项那一句、章内另外各项的关键机制（防止侵占）。

## 顺序

对每一槽：读该 skill → 对照该 `\subsection` 正文与清单 → 按该文件改写 → 再进入下一槽。第 0 步只做一次，四槽共用那两张表。

### 0. 术语锁与对应链（整节共用）

读 [consistency.md](consistency.md)。填术语表与对应说明 6 句。抽本方法机制卡片。标明本项在若干项中的位置。表不写入 `.tex`。

### 1. 研究动机

读 [1-motivation.md](1-motivation.md)。四段起承转合；段首句按该文件骨架，润色时不改写。合段给出中英文全称与简称，只报与机制相关的 1–2 个数。

### 2. 方法设计

读 [2-method.md](2-method.md)。先总体框架（有图、有分步），再按数据流写模块五步闭环。不报准确率；预备知识已有的定义式不重出编号。

### 3. 实验分析

读 [3-experiment.md](3-experiment.md)。三层：实验设置 → 主要结果 → 消融与分析。有数字就有结论，宾语落到机制或任务难点。原论文没有的分析只提醒用户，不编进正文。

### 4. 本节小结

读 [4-summary.md](4-summary.md)。问题 → 动机（方法名独立成句）→ 方案思路 → 实验效果。减公式、减符号；消融不提；分析实验只留直接验证动机的一句。

### 5. 跨槽核对

四块都改完后，按 [consistency.md](consistency.md) 的“四小节前后一致”表核对，不一致先改，再去 AI 腔。

| 核对项 | 要求 |
|--------|------|
| 方法名 | 合段正式登场（中英文全称 + 简称）；方法、实验、小结用简称，不重释全称 |
| 术语一套 | 任务名、难点现象词、模块名、机制作用词四槽同锁 |
| 不足 ↔ 模块 ↔ 消融 | 承段 2–3 条不足，合段“首先 / 其次 / 最后”对齐；方法模块能落到这些点；消融能验证其中至少一条 |
| 机制作用词一套 | 合段“通过这种方式”、各模块收束、主表归因、消融结论、小结效果宾语，落到同一机制 |
| 数字一套 | 合段 1–2 个数 ⊂ 实验主表；小结 2–3 个代表数字与主表一致 |
| 对应链 | 本项关键变换能卡住章难点的某一根因；该根因能从现实需求长出；实验验证的是这一卡住。正文不写挑战编号 |
| 本项位置 | 未把另一项工作的关键变换写成自己的合段或模块 |
| 主语 | 通节“本节 / 本方法”，无“我们”“本文” |
| 槽边界 | 方法无准确率；小结无公式、无消融；动机无模块流程 |

### 6. 整节润色

读 [polish/academic-zh.md](../polish/academic-zh.md)，扫描范围限于本 `\section`。动机四段段首、方法“通过这种方式”、实验分点序号均不删。

## 常见问题

### Q：用户只说“润色【某方法名】”，要不要连章引言一起改？

**不要。** 一项成果止于该 `\section` 的四个 subsection。章引言、预备知识、本章小结是章级插槽。

### Q：四个 skill 能不能一次读完再改？

**不要一次读完。** 按序读、改、再读下一份。跨槽核对在四块都改完之后做。

### Q：某一小节已经是范例定稿，还要不要动？

**对照清单扫一遍，通过则跳过，不要为改而改。** 仍须参加跨槽核对。

### Q：光标在本节小结，用户说“完整润色这一节”呢？

**走本文件，改整个工作节。** 只有用户明说“只改小结 / 只改动机”时，才回到入口按单槽派发。单槽派发仍须读 `consistency.md`。

### Q：四小节各自通顺，但术语对不上，算完成吗？

**不算。** 先按术语表改回同一套，再谈润色。
