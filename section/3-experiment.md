# 节内“实验分析”撰写

## 核心原则

**实验分析不是把论文表格搬过来加几句描述，而是用“动机→结果→比较→结论”四步把每个实验讲成一个完整论证。** 读者读完应知道：做了什么实验、结果如何、说明了什么。每个有数字的地方都要有结论，结论须扣方法动机或任务难点。

研究报告以已发表论文的实验部分为内容来源，主要从形式上组织。若需补充原论文没有的分析，只提醒用户补充了什么，不写进正文。

### 十条铁律

1. **先设置后结果。** 实验设置写全数据集来源、划分、预处理、基线、指标与超参；超参列表格，不散落在段里。
2. **每个实验四步走。** 实验动机（为了验证……，进行……实验）→ 引图表号 → 量化比较 → 结论归因。四步可融为一段，但逻辑缺一不可。
3. **有数字就有结论。** 报了量化结果就必须跟一句“表明……”“说明……”，宾语落到具体机制或任务难点，不写泛泛的“验证了有效性”。该机制须与动机合段锁定的作用词同族，并能指回章难点根因；不要把另一项工作的机制安在本项结果上。
4. **主实验详、消融精。** 主实验给多数据集逐条比较 + 平均提升 vs 次优；消融每组报关键数字与归因，不必逐条展开。消融组标签与方法模块名同一套。
5. **量化同时报绝对与相对。** “【指标】达到 a，较【基线】的 b 提升 d（相对提升 p%）”。百分点用“提升 x 个百分点”或“+x”。
6. **行文遵守入口通则。**
7. **图表字号略小于正文，至少为 `\small`。** 表环境开头写 `\small`（列多时可 `\footnotesize`）；图题已由模板设为 `\small`，子图题不大于 `\small`。
8. **表题在上、图题在下。** 按 GB/T 7713.1：`\bicaption` 写在 `tabular` 之前、`includegraphics` 之后。
9. **原文分析实验有图必须引入。** 消融、低资源、噪声、案例、效率等分析，凡源论文配有图或表，须引入并 `\ref` 引用，不得只写数字不附图。原文无图的组件消融可用表。
10. **实验验证对应链上的卡住，不是另起一套故事。** 主表趋势须能用本方法关键变换解释，并回到现实需求或难点现象。范式对比、组件消融优先用来证明“若无此变换，难点根因仍成立”。细则见 [consistency.md](consistency.md)。

## 三层结构

每个工作节的实验分析分为三个 `\subsubsection`：实验设置、主要结果、消融与分析实验。

### 第一层：实验设置

用加粗标签分段：`\textbf{数据集.}\;`、`\textbf{对比方法.}\;`、`\textbf{实施细节.}\;`。评估协议若较短则并入实施细节末尾（评估协议在后、实施细节在前），若较长或较特别则单列 `\textbf{评估协议.}\;`。

**数据集**：按类别列举，每类点名数据集与引用。写清划分惯例、种子比例、预处理方式。数据集统计列表格，不散落在段里。表格环境开头写 `\small`。

**对比方法**：按类别分组，每类点名方法与引用。注明复现方式：“除特别说明取自原论文的结果外，基线均以公开代码在公平设置下复现。”

**实施细节**：从原论文提取完整细节，不要过度简化为一句。须对照原论文核对学习率、权重衰减、批大小等数值。内容清单（按论文出现顺序逐句换行）：编码器隐层维度与层数；各特征维度；训练轮数与批大小；优化器、学习率、权重衰减；关键超参；迭代训练策略或特殊训练约定；硬件配置；超参搜索方式与指标。若超参较多，列表格给搜索范围与分布，段里只点名关键取值。

**评估协议**（视情况单列或合并）：指标首次出现给公式，注明各符号含义。划分比例、运行次数、均值标准差报告方式。若协议简单，并入实施细节末尾即可。

### 第二层：主要结果

逻辑为：引表 → 逐数据集量化比较 → 趋势归纳 → 机理归因。

**段首句**：“表~\ref{...} 给出 X 与各基线在 N 个基准上的 Y 结果。”

**逐数据集比较**： “在 Z 数据集上，X 的【指标】达到 a，较此前最优 M 的 b 提升 d（相对提升 p%）。多个数据集可并列。

**趋势归纳**：给平均提升；点明规律（如“种子比例越低，相对增益越大”）。

**机理归因**：用与合段、方法收束同锁的机制词解释趋势。异常结果也要解释：“仅在【某集】上略低于最优……其主要原因在于……”。趋势所依的设定应能回到章引言现实需求或难点现象。

**多个主表**：每表后跟一段分析；两段分析之间可加可视化图作为机制证据的过渡。

### 第三层：消融与分析实验

每组实验用加粗标签开头：`\textbf{(N) xxx.}\;`。不再用“第 N 组 xxx。”等非加粗写法。每组仍走四步，但比主实验精简。

| 类型 | 动机 | 典型比较 | 结论指向 |
|------|------|----------|----------|
| 组件消融 | 验证各模块贡献 | 去模块 / 换模块后的降幅 | 哪个模块是性能主要来源 |
| 模态/输入消融 | 验证各输入贡献 | 去掉某一输入后的降幅 | 哪个输入贡献最大，与任务难点是否一致 |
| 范式对比 | 验证建模范式选择 | 改造为其他范式后的降幅 | 直接验证动机段对范式的判断 |
| 低资源/噪声分析 | 验证困难设定下的优势 | 不同比例/强度下的曲线 | 设定越难优势越明显，归因机制 |
| 可视化分析 | 验证机制按设计工作 | 注意力 / 嵌入可视化 | 现象与设计一致 |
| 效率分析 | 验证精度与效率兼顾 | 精度-运行时间散点 | 在精度与效率上均可兼顾 |

**每组写法**：

- 段首用加粗标签：`\textbf{(N) xxx.}\;`
- 动机一句：“为验证各模块的有效性，在……设定下设计 N 组消融实验。”（此处“有效性”可留，因后文会落到具体模块）
- 引表 / 图。源论文该实验若有图，必须引入。
- 逐变体比较，每个变体占一行，不用分号把多个变体连在一句。
- 末句收束：“这一对比直接验证了第 X 节的判断：……”（X 是本节动机，不是章引言挑战编号）

消融结论的宾语必须是术语表中的机制作用词。去掉的变体应对应合段某一点；若某组消融验证的是另一项工作的机制，不写进本节。

## 量化与结论句式

**量化句式**（三选一，按语境）：

- 绝对 + 相对：“【指标】达到 a，较 M 的 b 提升 d（相对提升 p%）。”
- 百分点：“【方法】在【数据集】上取得 x%，相对【基线】的 y% 提升 z 个百分点。”
- 增量记法：“【基座】接入【模块】后在【数据集】上由 a 提升至 b（$+d$）。”

**结论句式**（接在量化后）：

- “表明……是性能的主要来源。”
- “说明……对……不可或缺。”
- “与第 X 节关于……的判断一致。”
- “直接验证了……的判断。”
- “说明……具有通用增益 / 可扩展至……。”

**禁忌**：不写“实验结果证明了方法的有效性”；不写“取得了不错的成绩”；报了数字不跟结论。

## 定稿骨架（占位）

**实验设置**：数据集按类别列举，统计见表；基线分组；协议给划分、指标公式、超参搜索表。

**主要结果**：主表 → 逐数据集报绝对与相对；例外解释原因；趋势归纳；机理归因用合段机制词。

**消融与分析**：各组 `\textbf{(N) xxx.}\;`；组件消融指向模块贡献；范式对比直接验证动机判断；可视化走四步但不报数字。

## 特殊情况

### 评估协议单列

若评估协议较特别，单列 `\textbf{评估协议.}\;`。若协议标准，并入实施细节末尾。

### 补充分析的提醒

若原论文缺少某组消融或分析，只提醒用户“此处建议补充 XX 消融，验证 YY 机制”，不把补充分析写进正文。补充的量化数字须来自实际实验，不编造。

### 多主表的分段

每表后跟独立分析段；两段之间可插入可视化图作为机制证据过渡。

### 可视化实验的写法

不报数字，但仍走四步：动机 → 引图 → 描述现象 → 归因。

## 常见问题

### Q：实验设置要不要写很长？

**数据集、基线各一段，实施细节可多句但逐句换行。** 实施细节不能过度简化。

### Q：实施细节的数值从哪里来？

**从原论文提取并核对。** 若原论文数值与现稿不一致，以原论文为准，并提醒用户核对。

### Q：主实验要不要每个数据集都报数字？

**报关键数据集的逐条比较，再给平均提升。** 若数据集多，可分组报代表性数据集，其余见表。

### Q：消融实验要不要像主实验一样详细？

**不必。** 每组报关键变体的降幅与归因即可。每个变体各占一行。

### Q：原论文没有的消融要不要补？

**只提醒用户，不写进正文。**

### Q：分析实验要不要把原论文的图都放进来？

**必要的必须放。** 源论文若配了图或表，须引入并 `\ref`。不要把动机图、方法框架图塞进实验段。

### Q：可视化实验怎么写？

**走四步但不报数字。**

### Q：量化结果用绝对值还是相对提升？

**同时报。**

### Q：消融结论怎么扣动机？

扣方法动机、扣任务难点（X 是本节动机而非章引言挑战编号）、或点明方法特性。宾语须是术语表中的机制作用词。细则见 [consistency.md](consistency.md)。
