> **同时读：** [consistency.md](consistency.md)。模块名、收束宾语与动机合段锁定的机制作用词同一套；每个模块的设计理由须能指出它卡住了对应链的哪一环。
> **不要与：** [研究动机](1-motivation.md) 混淆。动机只点思路；本文件写模块、公式与设计理由。
> **写完后：** 对照动机合段与实验消融标签核对术语，再读 [polish/academic-zh.md](../polish/academic-zh.md)。模块段首句式须错开，不改 `\label{}`。锁定术语不得换成近义词。
> **行文通则：** 逐句换行；一句一意；正文不用破折号与直角引号；段首连词按本文件规定书写并保持稳定。细则见入口 [SKILL.md](../SKILL.md)“行文通则”。

# “方法设计”撰写

## 核心原则

**方法设计不是动机合段的扩写，而是按数据流把模块、公式与设计理由写清楚。** 读者只读这一小节，应能回答：输入是什么、各模块依次做什么、关键公式为何如此、输出交给谁。

动机节已经回答“为什么要做、从哪切入、方法叫什么”。本文件只写“怎么做”。不要把合段的“首先 / 其次 / 最后”再抄一遍当方法正文；也不要把实验数字提前报进来。

闭环作用在每个模块 `\subsubsection`，不是整节 `\subsection{方法设计}` 只套一次。

### 十条铁律

1. **先总体框架，再模块。** 必配框架图；正文按数据流逐步讲，子小节标题与模块对应。一个 `\subsubsection` 内若分多个子模块，每个子模块以加粗小标题开头（`\textbf{小标题}。`），不编号，与实验分析段的加粗标签格式一致。
2. **每个模块走五步闭环。** 段首动机 → 公式前直觉 → 编号公式 → 式中释义 → 收束作用句。总体框架不套这五步。
3. **编号公式后写“式中，X 为……”。** 逐符号释义。不要改成“其中”或 where。不改 `\label{}`。
4. **每个模块补“为什么这样设计”。** 补的是原文篇幅砍掉的理由，不是新实验、不是新机制。
5. **不报下游准确率。** 数字留给实验分析；动机段已报过的 1–2 个数此处不必重复。
6. **主语用“本节 / 本方法”。** 不用“我们”“本文”。算法步骤可用“首先 / 其次 / 最后”，这是逻辑骨架，润色时不拆。
7. **预备知识已有的定义式不重复编号。** 用“沿用预备知识中的……”接到本方法用法。若把通用定义拓展到具体任务，只写变量对应、任务图与路径解释，以及相对通式多出来的设定；不要重推通式。
8. **对照源论文保真。** 不改数学环境；不新增原文没有的机制或数字；改写时不得丢掉原有 `\cite{}`。
9. **模块收束回扣对应链，术语与合段同锁。** 每个模块写完收束后自问：去掉本模块，动机承段哪条不足、章引言哪句难点根因会继续成立？答不出则收束太空或对应是假的。`\subsubsection` 标题、加粗小标题与合段“首先 / 其次 / 最后”用同一套模块名。细则见 [consistency.md](consistency.md)。
10. **行文遵守入口通则。**

## 总体框架

第一个 `\subsubsection` 固定为总体框架。它只负责全局数据流，**不套模块五步闭环**。

- 目的一句点明本节方法把输入变成什么输出（可与动机合段呼应，但不重复方法名释义）。
- 正文必须有 `\ref` 呼应框架图。
- 图题由模板设为 `\small`；图内文字须 `\small` 或更小。
- 分步与图上的模块顺序一致，与后文 `\subsubsection` 标题一一对应。
- 这里可以出现符号，但不要展开推导。公式闭环从第一个技术模块开始。

**宜：** 【方法简称】的总体框架如图~\ref{fig:xxx-framework} 所示，方法分为若干步：(1) ……；(2) ……；(3) ……。

**忌：** 在总体框架里推导损失通式或写出迭代细节；把“为了 / 考虑到”五步套进总体框架，再在模块里重复一遍。

## 模块五步闭环

每个技术模块 `\subsubsection` 按同一顺序写。句模如下（按用户指定原文使用，不改写）：

- 每个小节开头要有一段话介绍目的或者动机，类似于“为了xxx”“考虑到xxx”“在xxx之后，本方法进一步xxx”。
- 核心公式前面要有 intuition。
- 公式后是符号解释。
- 然后一句话介绍作用，类似于“通过这种方式，本方法能够xxx”“该模块利用xx，缓解、建模、实现、提升xxx（前面的动机或者子动机）”。

写成固定五步：

```text
段首动机（为了 / 考虑到 / 在……之后，本节进一步……）
→ 核心公式前的直觉（算子为何对应当前约束）
→ 编号公式（原式不动）
→ 式中，符号释义
→ 收束作用句（回扣本段动机：缓解 / 建模 / 实现 / 提升）
```

### 第一步：段首动机

用一两句话说明本模块要消除什么约束。不要先出公式。

| 骨架 | 适用 |
|------|------|
| “为了xxx” | 本模块直接服务于一个正向目标 |
| “考虑到xxx” | 本模块针对一个已暴露的缺陷 |
| “在xxx之后，本方法进一步xxx” | 本模块承接上一模块的输出 |

**段首句式必须错开。** 相邻模块不要都用“为了”。典型顺序是“为了”→“考虑到”→“在……之后”。

### 第二步：公式前直觉

一两句说明所选算子为何适合当前约束。这是“为什么是这个公式”，不是符号表。直觉讲机制能力；式中只释义新符号。同一套角色不要在直觉、式中、收束三处各说一遍。

### 第三步：编号公式

给出变换、目标或约束。公式顺序与实际计算顺序一致。润色时不改 `\label{}`、数学环境与符号约定。源论文因篇幅压缩掉的中间步骤可以补回，但预备知识已覆盖的标准定义不重出编号公式。

### 第四步：式中释义

编号公式后立刻写“式中，X 为……；Y 为……”。只解释本式新出现或本模块首次赋予含义的符号。

### 第五步：收束作用句

- “通过这种方式，本方法能够xxx”
- “该模块利用xx，缓解 / 建模 / 实现 / 提升xxx”

宾语必须是**本段开头的动机或子动机**，须与动机合段锁定的机制作用词同族，并能指回章难点根因的一环。不要收束成另一套评价（“提升表征质量”“增强鲁棒性”）。“通过这种方式”是逻辑骨架，润色时保留。

### 一个模块多条核心公式

每条核心公式各自走一遍“直觉 → 公式 → 式中 → 收束”。辅助公式不必再套完整五步：主公式走完闭环后，用一两句接到辅助公式，仍写“式中”。

## 常见问题

### Q：总体框架要不要走五步闭环？

**不要。** 总体框架只给目的、图和数据流。五步闭环从第一个含核心公式的技术模块开始。

### Q：动机合段已经用“首先 / 其次 / 最后”讲过若干步，方法里还要再写吗？

**要写做法，不要抄贡献清单。** 方法段按模块写出公式、直觉与接口。

### Q：预备知识已有的通式要不要在方法里再写一遍？

**不重出编号公式。** 方法段写本方法如何用。源论文里被砍掉的**设计理由**要补。把通式拓展到具体任务时，只写变量对应与多出来的设定。

### Q：一个 `\subsubsection` 里有两条核心公式，收束写几次？

**各写一次。** 挤在一段末尾只说“是……的基础”，等于两条公式都没有闭环。

### Q：收束能不能写“是……的基础”“为后续模块奠定基础”？

**不能单独这么收。** 收束必须回扣本段动机。可以提到下一模块，但宾语仍须具体。

### Q：直觉和“式中”有什么区别？

**直觉回答“为何用这个算子”，式中回答“符号是什么”。** 收束只写作用，不再第三次解释同一套角色。

### Q：润色时公式能不能改得更漂亮？

**不能改标签与数学环境。** 不要为了“补全”而新增原文没有的模块或超参。改段落前先列出该段原有 `\cite{}`，改完核对仍在。

### Q：方法段要不要报实验数字？

**不要。**

### Q：一个 \subsubsection 内的子模块要不要加粗小标题？

**要。** 每个子模块以 `\textbf{小标题}。` 开头，不编号。小标题用词与动机合段、消融组标签锁定为同一套。

### Q：方法段怎么承担“各项成果对应到难点”？

**靠每个模块的设计理由与收束，不靠写挑战编号。** 若某模块对对应链没有贡献，检查它是否不该成为独立 `\subsubsection`，或是否其实属于另一项工作。
