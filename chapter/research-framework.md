> **何时读：** 用户要做研究框架 / 研究框图 / 总体框架图，或写正文前发现台账未锁。
> **不要与：** [绪论](introduction.md) 的研究内容节混淆。本节先锁格子与台账；绪论只按已锁框架写顺承段与各条。
> **写完后：** 用户确认锁定后，把字段写入入口台账，再派发摘要 / 绪论 / 工作章。未锁定不得写正文。

# 研究框架（先手工锁定，再写报告）

本文件只解决**研究框架**：柱怎么切、难点两点是什么、成果归哪一柱、框图怎么摆。不写摘要、绪论或方法细节。

**本 skill 不替用户发明课题。** 框架必须由用户根据已有成果拍板；代理只清点素材、给出切分选项、把已确认内容填进格子。用户未说「锁定 / 确认」之前，禁止开始写报告正文。

## 何时必须先走本文件

出现下列任一情况，停写正文，改走下方流程：

- 用户要新写研究报告 / 出站报告 / 学位论文，但还没有总体框架图或台账。
- 柱名、难点两点、成果归属、顺承箭头互相打架。
- 只有论文清单，尚未决定「几柱、每柱两点难点、每柱几项成果」。
- 用户点名「研究框架 / 研究框图 / 总体框架图 / 图 1.x 框架」。

已锁定且用户只要改句子：不要重开框架讨论，按入口台账写。

## 前提：先有成果和素材

缺素材不要编框架。先向用户要（有什么用什么，不必齐）：

| 素材 | 用来锁什么 |
|---|---|
| 已完成论文 / 预印本 / 技术报告 | 一项成果的任务、方法中文名、机制 |
| 实验主表、消融、设定说明 | 该项打什么现象、验证落在哪类任务 |
| 各文动机图 / 任务示例图 | 后文研究问题配图；**不要**当总体框架图 |
| 立项任务书（若有） | 只抽应用口径与对象工作定义，不抽「拟开展」路线 |
| 已有章节草稿或目录 | 章题是否已接近柱全称 |

每一项成果先登记一行（内部草稿，不写入 `.tex`）：

```
【成果中文名】｜任务对象｜关键机制｜所打现象（尚未定稿）｜验证场景｜拟归哪一柱（待定）
```

登记不全可以往下走，但**空行对应的格子不得填假方法名**。

## 框架要锁的字段

与入口台账对齐。框图上出现的词必须是下表原词，不要另起近义。

| 字段 | 框图上 | 要求 |
|---|---|---|
| 题目 | 顶栏 | 与封面轻呼应；不要为好看改成另一套题目 |
| 各柱全称 | 「研究内容 N：…」 | = 工作章章题；带任务类后缀（学习 / 建模 / 检测 等） |
| 各柱短名 | 一般不上图 | 留给摘要「在……方面」 |
| 各柱中名 | 一般不上图 | 留给摘要「具体来说」收束 |
| 每柱两点难点 | 「难点挑战」 | 短短语；现象不是解法入口；两点不要能合成一句 |
| 每柱成果 | 「研究成果」 | 已完成工作的中文名；2–3 项常见，不必强行凑满 |
| 分打关系 | 不上图，写入台账 | 谁打难点 A、谁打难点 B；兼打须说清主次 |
| 布局与箭头 | 色块 + 箭头 | 横跨支撑、左右顺承；无关系不要画箭头 |

另锁、但**默认不写进框图**：整体难点（情况名）、互为依据句、应用名、英文方法简称、实验数字。

## 制作顺序（用户拍板）

每一步先给选项，等用户选或改，再进入下一步。不要一次生成「完整框架」让用户只能全盘接受。

### 1. 按任务聚类，不按论文篇数

把登记表按**判定目标 / 输入对象**归堆，不要按会议、年份或「先发的放第一柱」。

试切时问三句：

- 这一堆是不是同一类要判定的事？
- 拿掉其中一篇，这一柱是否仍能独立成章？
- 两堆是否其实在打同一现象、只是方法不同？（若是，应并柱，不要为了图好看拆开）

柱数以当前稿为准，不必四柱。一柱对应后文一个工作章。

### 2. 定顺承：有没有底座柱

常见两种布局（学结构，不绑死柱数）：

**布局 A（有支撑柱）：** 一柱横跨全宽，其成果作为后列的表征 / 表示 / 前置条件；其余各柱并排，按「谁为谁提供输入」从左到右。

**布局 B（全并列）：** 各柱同级并排，只用左右箭头表示顺承；没有「一柱托住其余」。

不要为对称硬造底座。没有支撑关系就用布局 B。柱与柱「相对独立又能顺承」：独立 = 可单独验证；顺承 = 前柱输出能成为后柱输入，而不是后柱必须复述前柱方法。

### 3. 每柱锁两点「难点挑战」

每柱恰好两点，供后文 `\textit{}` 使用。句模优先短、可对举：

```
【现象A：易… / 难…】
【现象B：易… / 难…】
```

合格：读者能从短语看出「现有做法在什么机制上会失败」。

不合格：

- 写成方法入口（「缺少波动传播」「未用信息瓶颈」）
- 写成任务名重复（柱叫「对齐」，难点叫「对齐很难」）
- 两点实为同一句话拆开
- 用整体难点（情况名）顶替具体难点，或反过来

同一柱内各项成果合起来必须能分打这两点；做不到就改难点，或把不相关成果移走，不要在图上留空难点。

整体难点（研究背景 enumerate、研究问题标题用的情况名）在框架讨论里可以一并起草，但**框图「难点挑战」格只放具体难点两点**。两套词不要混进同一格。

### 4. 成果归柱，并写分打

把登记表的每一项成果写入恰好一柱。一项成果不要同时出现在两柱格子里。

每项写清：

```
【成果中文名】→ 主打【难点A 或 B】；兼及【另一点或不兼】
```

一柱两项也可，三项常见；不要为了和邻柱一样高而虚构第三项。成果名用中文机制/任务表述，与后文章内节题同族。英文简称可附在台账，**框图主标签用中文**。

### 5. 三层命名只在台账对齐，框图只用全称

| 层 | 用在 | 形态 |
|---|---|---|
| 全称 | 框图「研究内容 N」、章题、摘要「开展……」 | 含限定词的完整任务名 |
| 中名 | 摘要「具体来说」收束 | 带「学习 / 建模」一类，短于全称 |
| 短名 | 摘要「在……方面」、结论条题 | 更短方面名 |

三层不得叠床。框图不要同时写短名与全称。

### 6. 填格子、画箭头、停下来锁定

按选定布局填字，再画箭头：

- **向下 / 分流：** 支撑柱的成果指向后列各柱（「为后续提供……」）
- **向右：** 并列柱之间的输入—输出（「先…再…」）
- 不要把「互为依据」画成双向空心箭头，除非用户明确要求；该句留给绪论正文

然后列出待确认清单，请用户逐条拍板。用户改一词，格子与台账同步，禁止用近义润回去。

锁定口令：用户明确说「锁定 / 就按这个 / 确认框架」。锁定后，写正文不得改柱数、难点两点、成果归属；要改必须先回到本文件重锁。

## 框图怎么画（总体框架图）

学的是「题头 + 每柱三层（内容 / 难点 / 成果）+ 支撑或顺承箭头」这一骨架。工具不限（PPT、Keynote、draw.io、TikZ 均可）；**先锁文字再绘图**。

### 格子骨架（布局 A）

```
┌──────────────────────────────────────────────┐
│ 题目                                         │
├──────────────────────────────────────────────┤
│ 研究内容一：【柱一全称】（横跨）               │
│ 难点挑战  【难点A】          【难点B】        │
│ 研究成果  【成果1】【成果2】【成果3】          │
│              ↓ 支撑          ↓               │
├────────────┬────────────┬────────────────────┤
│ 研究内容二 │ 研究内容三 │ 研究内容四          │
│ 【全称】   │ 【全称】   │ 【全称】            │
│ 难点挑战   │ 难点挑战   │ 难点挑战            │
│  A / B     │  A / B     │  A / B              │
│ 研究成果   │ 研究成果   │ 研究成果            │
│  …         │  …         │  …                  │
│         →             →                       │
└────────────┴────────────┴────────────────────┘
```

布局 B 去掉横跨条，各柱同一行，只保留左右顺承箭头。两柱、三柱同样套用，不要为「看起来像四柱」补空列。

### 绘图规则

1. **每柱三层标签固定为「研究内容 / 难点挑战 / 研究成果」。** 不要改成「科学问题 / 创新点 / 技术路线」。
2. **一柱一色系**，难点格与成果格同色浅底，标题条深底。不要一柱多色。
3. **字比箭头重要。** 先保证难点短语与成果名能读完，再加装饰。
4. **不上图：** 准确率与 Hits@k 一类数字、应用全称列表、长段关系句、模块框图、公式。
5. **图题**用「总体研究框架 / Overall research framework」，不要写成某方法网络结构。
6. 定稿图嵌入绪论「研究内容与贡献」节；后文各章引言可引用同一图，不另起一套柱名。

### 与绪论正文的对应

框图锁定后，绪论研究内容节只做三件事：放图、用顺承段解释箭头、按柱写「针对整体难点 / 缓解具体难点 / 提出哪些成果」。不要在正文里新增图上没有的柱或成果。贡献 enumerate 按柱收方法名，仍不报数字。

## 与写报告的分工

| 本文件（框架） | 入口台账与各章 skill |
|---|---|
| 柱怎么切、难点两点、成果归谁、箭头 | 用已锁词写摘要漏斗、绪论漏斗、工作章、结论 |
| 总体框架图格子 | 研究内容节配图；章引言两点难点原词 |
| 用户拍板锁词 | 润色不得改锁词 |

框架未锁就写正文，几乎一定会出现：摘要分条与章题不一致、绪论难点与章引言两套词、相关工作按论文篇数而不是按柱综述。

## 停写检查

- [ ] 每项成果都能指向用户提供的素材，无虚构方法名
- [ ] 柱按任务聚类，不是按论文篇数
- [ ] 每柱两点具体难点是现象，能被该柱成果分打
- [ ] 整体难点与具体难点已分开起草（情况名不上框图难点格）
- [ ] 布局与箭头和「谁为谁提供输入」一致；无关系无箭头
- [ ] 三层命名已写入台账；框图只用全称
- [ ] 用户已口头或书面锁定；台账已填，正文尚未开写（或仅改与框架无关的句子）
