# 工作章“引言”撰写

## 核心原则

**章引言是全章的路线图，回答四个问题：本章做什么、为什么难、因此研究什么、具体做哪几件事。** 好的章引言让读者在 400–800 字内把握全章脉络，并看出各项工作如何经方法机制卡住两点难点、难点又如何从现实需求长出。

### 五条铁律

1. **引言控制为两段话**：第一段 = 现实需求 + 任务/术语 + 两点难点（框架定位可选，并入任务句或第二段过渡句，不单独成段）。第二段 = 因此过渡 + 若干项工作（过渡不要拆成第三段）。不分三段或更多，避免引言变成综述。
2. **开头从现实需求引入**：每章第一句都不承上。从本章对象的现实需求切入，举映射后文路线的具体例子，再落到核心问题。不要写“第 X 章给出……”，也不要写“当关注点从 X 转向 Y”。不能直接跳到空泛背景。
3. **难点与工作经方法机制对应**：两点难点与若干项工作之间要有可追溯的对应关系，读者能看出哪项工作卡住了哪条难点的根因。对应靠深入理解各方法实际做了什么（输入、关键变换、损失惩罚什么、刻意不做什么），不要只把方法名贴到难点名旁边。两项工作可以打同一难点的不同层；一项工作可为后一项铺路，但不得把后一项的关键变换提前写成自己的。难点必须从本段现实需求长出。工作节内如何把对应写进动机/方法/实验/小结，见 [section/consistency.md](../section/consistency.md)。
4. **句式全文统一**：难点用"一是\textit{xxx}问题：…二是\textit{xxx}问题：…"，过渡用"针对上述难点，本章节开展\textit{章题}研究"，工作用"首先，提出xxx，…其次，提出xxx，…最后，提出xxx，…"。各章保持一致。
5. **行文遵守入口通则。** 逐句换行，一句一意，正文不用破折号与直角引号，段首连词稳定（第一段从现实需求起；第二段过渡“针对上述难点”、工作“首先 / 其次 / 最后”）。

## 六层结构

以下是内容层，成文只排成两段：第一段写第 1–4 层，第二段写第 5–6 层。不要按层各空一段。

### 第一层：现实需求引入（1–2 句）

直接从本章对象的现实需求起笔，举映射后文路线的具体例子，再落到核心问题。

**写法（默认）**：先给映射后文各条路线的生活例子，再落到本章任务。例子须一一对应后文章内工作，不能泛泛举例。

**写法（背景句+具体例子）**：也可先给一句背景点题，再用冒号接具体例子，适合“缺失 / 稀疏”类任务。背景句须简短，冒号后紧跟映射后文路线的例子。

**各章均不写承上句**：第一句直接写现实需求例子。章与章之间的主线放在因此过渡的“为……提供基础”，不靠开头回指上一章。

### 第二层：框架定位（可选，1 句）

点出本章在总体框架中的位置。若用户明确不需要勾连第一章框架图，可省略此层，改为在任务定义前加一句过渡。

```
本章对应图~\ref{fig:overall-framework} 的研究内容N：【章题全称】
```

框架定位并入第一段任务句或第二段因此过渡，不要单独成段。

### 第三层：任务/对象定义（2–4 句）

给出本章任务的形式化定义，必要时定义关键术语。

- 任务定义：给定……，任务是……；对象有两类时分开写。
- 术语定义用 `\emph{}` 标记，与章引言的 `\textit{}` 难点名区分开。放在任务定义之后、难点之前。
- **术语与难点名密切相关时可融入难点描述**，不单独成句。
- 通用概念（图、序列等）通常不需要术语定义。

### 第四层：两点难点（1 段）

列出本章面对的两点核心困难。

**任务到难点的过渡句**：任务定义之后、难点之前，须有一句过渡，点出现有方法如何做、仍面临什么挑战，再接"一是"。过渡句中的方法描述须与难点一的根因呼应。

```
[过渡句] 一是\textit{难点名}问题：具体描述。二是\textit{难点名}问题：具体描述。
```

- 难点名用 `\textit{}` 标记，4–8 个字；`\textit{}` 内必须是绪论已锁该柱两点原词，解释放在冒号后。
- 每点先说现象再说根因。
- 可配统计数据支撑（须已核）。
- 两点之间有递进：第一点偏机制层面，第二点偏信息/知识层面。
- 难点内若分子点，各子点单独成行，不用分号连在同一句。
- 难点条数固定为 2 条。每条根因须能从第一层现实需求推出来。写完自问“若现实中不存在该需求，这条难点还成不成立”。
- 难点现象词一经 `\textit{}` 锁定，后文各项工作句与各工作节不得另起近义难点名。

### 第五层：因此过渡（1 句）

```
针对上述难点，本章节开展\textit{章题}研究，[一句话定位]，为后续/……提供……基础。
```

- 章题用 `\textit{}` 标记，与目录中的章标题一致。
- 如果若干项工作有明确的方法学主线，在过渡句中点出。
- “为……提供基础”点出本章在全文中的定位，与下一章衔接。
- 本句与若干项工作同属第二段，不要在过渡句后空一行另起一段。

### 第六层：若干项工作（1 段）

```
首先，提出xxx，[核心思路]，[关键机制]。其次，提出xxx，[核心思路]，[关键机制]。最后，提出xxx，[核心思路]，[关键机制]。[实验验证]。
```

- 每项以"首先/其次/最后，提出xxx"开头，方法名紧跟。
- 每项的描述要呼应第四层的难点：写的是该方法的关键变换如何卡住该难点的根因。写之前须读懂该方法（至少总体框架与核心损失）。
- 两项可打同一难点的不同机制层；后一项可沿主线加深前一项未打完的根因；不要为了“一项对一个”把各项工作硬拆成与两点难点无关的若干套故事。
- 每项覆盖 2–3 个关键机制，但不展开细节；这些机制词将成为该工作节的术语锁上游。
- 末句概括实验："若干项工作在……等基准上验证"。落到验证场景或具体能力，不要空写“验证了方法的有效性”。
- 方法名在此处正式登场（中英文全称+简称），后文用简称。
- 各项工作的顺序与正文中小节的顺序一致。
- 实验验证句要与本章实际实验对应。

## 各章如何填（从当前稿取，不预填课题词）

写某章引言前，从该章与绪论台账抽出：开头现实需求例子（须映射后文各条路线）、框架定位编号、任务/术语、两点 `\textit{}` 难点、因此过渡（含“为……提供基础”）、各项方法名与机制词。各章第一句均不承上。

## 常见问题

### Q：章引言和节引言（研究动机）有什么区别？

**章引言**是全章的路线图，覆盖全章所有工作，不展开任何一项的细节。**节引言（研究动机）**是单节的开头，只讲这一节的任务、不足与切入角度。

### Q：章引言第一句要不要承接上一章？

**不要。** 各章第一句都不承上，直接从本章现实需求起笔。章与章的主线靠因此过渡的“为……提供基础”点出。节动机的承上仍按 [研究动机](../section/1-motivation.md) 写。

### Q：术语定义放在哪里？

放在任务定义之后、难点之前。术语与难点名密切相关时可融入难点描述。

### Q：若干项工作的实验验证要不要报具体数字？

**不要。** 只说"在 N 个基准上验证"或落到具体能力，不报准确率。具体数字留给实验分析节。

### Q：如果本章若干项工作分属不同类型，怎么组织？

在工作段中按类型分组描述，末句也分类型报实验。不要强行用同一句概括不同类型的实验。

### Q：因此过渡句和若干项工作要不要分成两段？

**不要。** 二者同属第二段。层次靠句式区分，不靠再空一行。

### Q：两项难点、三项工作，如何对应到现实需求？

**先读懂各个方法，再写难点与工作句，不要贴标签。** 对应链是：现实需求里要做成的事 → 机制上卡在哪（两点难点）→ 各方法的关键变换卡住了哪一环。合法格局包括两项打同一难点的不同层。细则见 [section/consistency.md](../section/consistency.md)。

### Q：框架定位一定要引用第一章框架图吗？

**可选。** 若用户明确不需要，可省略。

### Q：任务定义之后能不能直接写"一是"难点？

**不能。** 须有一句过渡，点出现有方法如何做、仍面临什么挑战，再接"一是"。
