> **何时读：** 用户要写结论章，或说“写结论 / 总结与展望 / 工作总结 / 未来工作”。
> **不要与：** 工作章 [本章小结](technical-chapter-summary.md)、[摘要](abstract.md) 混淆。本章小结收一章若干项工作；摘要是开门代理且不写展望；本章收全书，特别关注与前文的呼应关系。
> **写法：** 两节、按柱复述贡献、未来三拍。绪论贡献条须被结论几乎同词收回。学对应链与两节句模，不搬范例柱名。
> **写完后：** 读 [polish/academic-zh.md](../polish/academic-zh.md)。
> **行文通则：** 逐句换行；一句一意；正文不用破折号与直角引号；段首连词按本文件规定书写并保持稳定。细则见入口 [SKILL.md](../SKILL.md)“行文通则”。

# 总结与展望

## 核心原则

**结论是全书漏斗的收口：用同一套柱名、难点现象词、机制词、互为依据句与主线，把前文收回来，再从每柱已做工作长出下一问。** 好的结论让读者在两节内看清“全书做了什么、还盖不住什么”，并且不另起一套故事、不另开一套创新点。

研究报告与学位论文用两节：工作总结 → 未来工作展望。贡献条几乎是绪论贡献的同词复述，未来每条先复述已做再写“然而”与“如何”。本文件学的是对应链与两节句模；柱名用绪论已锁的那一套。体裁若只需阶段小结，仍按柱收，不要改成创新点清单。

不要再当三段式草稿（工作总结 / 主要创新点 / 不足与后续）重写，也不要把已压缩掉的互为依据段、具体难点复杂情况段补回去。

### 七条铁律

1. **两节收全书，不过第三段。** 主要包含工作总结和未来工作。不要单开“主要创新点”，不要把局限与展望拆成两个 enumerate。章首导语点题并预告两节路径。
2. **工作总结按柱收，不按论文篇数报流水账。** 各条对应各工作章。一章多项工作收进该柱一条，不要拆成与绪论贡献条数不一致的条目，也不要把各章小结粘成一章。
3. **贡献条与绪论研究内容同词。** 柱名、难点现象词、机制词须与绪论机制词、组织节节题同族。每条：短方面名 + 围绕柱全名 + 提出方法 + 机制打该柱两点难点 + 相对前人补了什么。对应靠同一现象词和同一机制，不靠“回应科学问题一”这类编号。
4. **不另报一套准确率。** 默认工作总结不报数字。禁止在结论里改写成另一套指标或另一组数据集。
5. **未来一条柱对一条，内部三拍：已做 → 然而 → 如何。** 已做压缩该柱工作总结的机制；然而写清做不到什么、在什么设定下；如何给出可做的下一问，须从该局限长出，末句各条错开。不要另起无关清单，不要写“进一步提升性能”，不要为贴内容而改已锁标题。
6. **章末未来升一层，再写进全书未来。** 各章 `\section{本章小结}` 末句的“未来”是方法内部技术债。全书未来是该柱问题设定之外的下一研究问题。可以吸收章末技术债，禁止逐章复制“本文将在未来进一步……”。
7. **主语用“本文 / 本报告”。** 这是全书层，不是章内“本章 / 本节”。柱名、具体难点、主线、对象句、应用全称必须与绪论同词；互为依据句若出现须原词，成稿散文可不展开该句。

## 改定经验（须守）

以下条款来自结论多轮改定。写或改结论时先按此对表，再动句子。用户当场改定一词后，本文件与 `.tex` 同步，禁止用近义润回去。锁词仍跟当前稿台账。

### 成稿已是两节，按成稿压缩漏斗

工作总结散文四拍，不要写回更长的展开：

1. 对象句：含锁定条件 + 对象。
2. 应用句：「通过【做法】，不仅能对【学术侧】起到推动作用，也能为」应用全称「提供知识支撑」。用研究意义全称，不要用章首缩写。
3. 主线一句 + 各方面一句：沿台账主线展开；研究内容涵盖各柱全名。
4. 收束：「综上，本文的主要贡献总结如下：」不要写成「研究内容贡献总结如下」。

**不要写回：** 互为依据全文；各柱具体难点复杂情况段；「通过 A，……；通过 B，……」按柱分工长段；「突破现有研究的难点问题」；章首再叠锁定条件。章首成稿为「本章节简要总结本文围绕【研究目标】开展的研究工作，并根据技术研究发展和现实世界需求，对未来研究内容进行展望。」

### 贡献条：短方面名 + 围绕柱全名 + 提出方法

```
\item \textbf{【短方面名】方面}，围绕【柱全名】，提出[方法名]。
      具体来说，[机制打难点 A]。
      并且 / 同时 / 进一步 / 由此 / 再以[机制打难点 B]。
      和前人……相比，本文的方法能够……。
```

方面名用短名，柱全名放在「围绕」后。不要只留短名或把 `\textbf{}` 改成柱全名。连接词各条不要完全同构。默认不报准确率。前人对比必须有谓语，不要写成「和前人【名词短语】相比」缺动词。

### 未来标题从该柱设定外长出，先衔标题再改内容

各条标题是已完成工作的**外延**，不是“更好的本法”。用户改的是标题本身时，一次只改锁定短语。禁止为贴新内容而擅自换题。

**标题与内容衔接：** 用户要保留机制名、又改「然而 / 如何」时，不要另起一条新题去贴内容。用已做设定说明标题中的机制为何不够，再接到新设定。热点范式（如大模型）必须服务于该缺口，不是另起热点。

不要把章内已解决的设定再写成结论缺口。

### 「如何」末句必须错开

禁止各条都以「亟待进一步研究」收束。末句须能扣该条「如何」的性质（理论保证 / 架构设计 / 方法探索 / 设定检验），不要换成同义套话。

### 结论内部（同一套词走完两节）

```text
章首导语（围绕研究目标 / 总结然后展望）
  → 工作总结散文（对象含锁定条件 + 应用全称 + 主线 + 各柱全名）
    → 工作总结各条（短方面名 + 围绕柱全名 + 方法 + 机制打两点难点 + 相对前人）
      → 未来帽子（收回各柱 + 仍有问题）
        → 未来各条（已锁或新拟标题；该柱已做 → 然而缺口 → 如何；末句错开）
```

**柱名锁死示例（学结构，不把示例方法名写入当前稿）：** 事件类别粒度精细 → 细粒度事件检测 → 类别精细难区分 / 类别数据不平衡 → 该方法（类别相关性 + 实例相关性）→ 未来“低资源事件检测”（相关性增强在相关类别也少时失效）。当前稿各柱同理。

### 结论外部（前文是展开，结论是收口，不是新故事）

| 前文锁的东西 | 结论必须对上 |
|---|---|
| 互为依据句 | 若写须原词。成稿散文已压缩，不强制展开。见 [绪论](introduction.md) |
| 主线 | 工作总结散文与未来帽子同一主线 |
| 各条线索名 / 各工作章章题 | 工作总结各方面名；未来各条各对一柱 |
| `\textit{}` 难点现象词 | 工作总结每条机制须打回该柱两点难点原词。见 [章引言](technical-chapter-intro.md)、[本章小结](technical-chapter-summary.md) |
| 绪论研究内容的机制词 | 工作总结“具体来说”机制；不要换成另一套近义 |
| 绪论贡献条目与数字 | 结论不另开创新点节。若点证据，用已锁口径 |
| 各章本章小结的若干项工作与末句作用 | 压进该柱一条，不展开各项量化清单；章末“未来”升一层后再写入对应未来条 |

写结论时只收回已锁定的词，不要在结论给柱或难点改名。相关工作章不在结论里评述；工作章细节、公式、消融留给各章，结论不重写方法。

#### 各条 enumerate

```
\item \textbf{[短方面名]}，围绕[柱全名]，提出[方法名]。
      具体来说，[机制 1，打难点 A]。
      并且 / 同时 / 进一步 / 由此 / 再以[机制 2，打难点 B]。
      和前人……相比，本文的方法能够……。
```

**写法要点：**

- `\textbf{}` 用短方面名；柱全名放在「围绕」后，须与绪论研究内容条目标题、组织节节题同族。
- “具体来说”只写卡住两点难点的关键变换，不写模块内部公式，不把该章各项工作展开成若干小段。连接词各条不要完全同构。
- 一章多项工作收进同一条。
- 相对前人写方法学位置，须能在相关工作章空白处站住。前人对比须有谓语。
- “据本文所知，本方法是首个……”仅当相关工作章空白能站住时才写；默认以机制与缺口为主，不堆“首个”。
- 每条不要都用“针对……提出”起句。方面名已经标明针对哪一柱。默认不报准确率。

**不要：** 按论文题目报流水账；把本章小结的绝对 / 相对指标清单搬进来；工作总结各段只报数字、不回扣难点原词；另写一条去重复绪论贡献。

### 未来工作展望

#### 帽子段（2 句）

```
本文围绕【研究目标】中的……问题，研究了【各柱短名】【N】个子任务。
尽管本文已取得了部分进展，但仍有很多问题亟待解决，在未来的研究中将继续探索以下问题：
```

主线词与工作总结相同。不要在帽子里开列方法名。

#### 各条 enumerate（与各柱 1:1）

**每条内部三拍，学未来条三拍：**

1. **已做：** 压缩该柱工作总结里的机制，让读者知道局限从哪长出来。
2. **然而：** 本文设定盖不住的具体缺口。写清做不到什么、在什么设定下。
3. **如何：** 可做的下一问。可以点近年范式，但必须从该“然而”长出，不能另起无关热点，也不能为贴热点而改掉已锁标题。

```
\item \textbf{[下一研究问题名称]}，
      本文针对[该柱已锁定难点]，主要[已做机制]。
      然而，[具体设定下做不到什么]。
      如何[可检验的下一问]，[末句按条错开]。
```

**标题怎么起：** 例如“低资源事件检测”“生成式事件抽取”“广义事实性识别”——都是已完成工作的外延，不是“更好的【本法】”。当前稿各条标题从该柱设定外长出。不要叫“更强的【本法】”或“进一步的【本任务】”。

**章末未来如何升一层：**

| 层 | 写什么 | 例子 |
|---|---|---|
| 本章小结末句 | 本法未解决的技术点 | 自适应类别图；级联错误传播 |
| 全书未来 | 该柱问题设定之外的下一问 | 相关类别也少时的低资源检测；生成式跨任务共享 |

结论未来可以吸收章末技术债，但收束必须落到下一研究问题，不要各条都写成“本文将进一步改进本章方法”。

**不要：** 局限一个 enumerate、展望另一个 enumerate，再靠“对应局限二”挂钩；各条未来只对应其中两柱；写“具有广阔前景”；把相关工作章文献缺口再综述一遍。

## 常见问题

### Q：结论和工作章本章小结有什么区别？

**结论**收全书，两节，主语“本文 / 本报告”，按柱收回机制并长出下一问。**本章小结**收一章若干项工作，含量化，末句只写对整体主题的作用、不写章号。不要把各章小结拼接成结论章。

### Q：为什么没有“主要创新点”节？

贡献写进工作总结 enumerate，绪论贡献条与结论贡献条同词，不在结论再列一套创新点。工作总结按柱收机制；数字留在各章主表。

### Q：工作总结要不要报准确率？

**默认不报。** 贡献条写机制与相对前人。禁止在结论里换指标、换数据集、或把本章小结的绝对 / 相对数字整段搬上来。

### Q：未来工作能不能跟本章小结末句一样？

**不能照抄。** 章末未来是方法内部技术债；全书未来是该柱设定之外的下一研究问题。可以吸收技术债进“然而”，但标题与“如何”必须升一层。

### Q：会不会写成摘要？

摘要面向未读正文的人，可独立；结论面向已读完全书的人，任务是呼应与收口。结论禁止重新定义任务、禁止铺背景数据、禁止再解释一次模块。

### Q：各条未来会不会不够“新”？

新不新取决于“然而”是否具体。空洞的“结合大模型”不算一条。热点必须接到已锁标题上的缺口，不能另起题。

### Q：用户要保留机制名、又改未来内容，怎么办？

**先衔接，后改句子，不换题。** 用已做设定说明该机制为何不够，再接到新设定。不要把内容名写进 `\textbf{}` 去替换已锁标题。

### Q：各条「如何」能不能都写“亟待进一步研究”？

**不能。** 按条错开：理论保证 / 研究设计 / 进一步探索 / 更开放设定中检验。
