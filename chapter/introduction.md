> **何时读：** 用户要写第 1 章绪论，或说“写绪论 / 研究背景 / 研究问题 / 研究内容 / 贡献”。
> **不要与：** 工作章 [章引言](technical-chapter-intro.md) 混淆。绪论是全书漏斗，不是某一章的两点难点+若干项工作模板。
> **写法：** 四节划分、段内句模与表述风格见本文件。学槽位与句模，不搬范例柱数与任务名。
> **写完后：** 读 [polish/academic-zh.md](../polish/academic-zh.md)。
> **行文通则：** 逐句换行；一句一意；正文不用破折号与直角引号；段首连词按本文件规定书写并保持稳定。细则见入口 [SKILL.md](../SKILL.md)“行文通则”。

# 第 1 章“绪论”

学基金写作的过程（先定模式、先锁证据、先建台账），不学基金的文体与槽位。本 skill 写的是已完成工作的全书漏斗；不要写成「拟开展」的立项书。研究框架（柱、难点、成果归属）须在写绪论之前按 [研究框架](research-framework.md) 由用户锁定。

**槽位跟本文件、锁词跟已锁框架与当前稿。** 章节划分、每个段落的组织逻辑和表述风格按本文件写；柱名、难点、互为依据句、主线、机制词，用已锁框架填入的台账，不为和范例文本对齐而改柱数。

## 先判断任务模式

动笔前先定模式，不要默认重写全文。

- **起草**：台账未锁，或用户要新写 / 重写某一节或整章。按下方写作顺序从台账写到组织节。
- **改写**：保留已核事实、柱名、难点现象词、互为依据句、主线；只修结构、对应、句模或文风。未经用户要求不改研究方向、不换柱数。
- **审计**：只报告问题、证据缺口和修改建议，不改 `.tex`。用户同时要求修改时，再按改写执行。

用户只点某一节时：先回对台账，再动该节；不要因改研究内容而另起研究背景的故事。用户当场改定一词后，全书与本文件同步该词，禁止用近义“润回去”。详见「改定经验」。

## 证据门禁

- 不编造文献、指标、论文状态或预实验数字。缺失标 `【待核：……】`，并给出最小补充清单。
- 三类不混写：**已核事实**用“已 / 表明”；**有文献支持的判断**用“现有研究提示 / 在……条件下仍难以”；**本文已完成工作**用“本文提出 / 已验证 / 实验表明”。禁止基金口吻的“拟研究 / 本项目 / 申请人”。禁止任务书式手工编号 `[1][2]`。
- 引用沿用工程已有 `\cite{}`，不要改成另一套命令。
- 贡献节不报准确率。研究问题里的统计须能追溯到用户材料或各章已核观察；无数字则定性，不为凑句式造数据。
- 禁止空夸：不写“填补空白、国际领先、必将、目前研究很少、尚无人研究”。“首次 / 率先 / 据本文所知”仅在相关工作章空白能限定适用范围时使用。

## 任务书怎么用

立项任务书只提供应用口径，不提供方法定稿。

- **可抽：** 现实场景、域/对象的工作定义、应用落到哪几条。
- **不可抽：** 拟开展但与已完成工作不一致的技术路线。
- **不可搬：** 主要学术成绩、进度、经费、考核指标。改成“本文”口径后再写入研究背景，不要留“本项目”。

## 先建两张表，再按顺序写

写任何一节之前先填下两表（内部草稿，不写入 `.tex`）。表建不成：若缺的是柱 / 难点 / 成果归属，先走 [研究框架](research-framework.md)；若框架已锁只是未从当前稿抽出，则填入口台账与「本报告台账」。表仍建不成，不要开始改句子。

### 表 A：锁定项

| 锁定项 | 要求 |
|---|---|
| 总命题 / 研究对象 | 1 句；章首导语与研究问题开篇同词。做法不是对象。图或其他数据结构是载体，不要写成研究对象 |
| 互为依据句、主线 | 全书原词；若当前稿无互为依据句则不编 |
| 各柱名 | = 研究背景收束的关键任务 = 研究问题所对之章题 = 研究内容条目标题 |
| 每柱两点难点 | `\textit{}` 短语；研究背景 enumerate 用**整体难点**作情况名，研究问题原词打开该柱两点 |
| 机制词 | 与研究内容、章引言工作句同一套 |
| 内容 → 贡献 | 一章一条；一章多项工作捆进该条 |
| 总体框架图 | 研究内容节必留；格子与 [研究框架](research-framework.md) 已锁框架同词 |
| 每问一张任务图 | 复用各章动机/任务示例图，新 label，不要用结果曲线 |

### 表 B：主张—证据—来源

| 主张 | 证据 | 来源 | 状态 |
|---|---|---|---|
| （研究问题各问统计或例子） | 数字或定性观察 | 数据观察 / 文献 / 用户给定 | 已核 / 待核 |

研究问题各问的统计必须入表。贡献节不写入准确率。工作章与结论若点证据，口径以各章实验主表为准，不另报一套。

### 写作顺序

0. 研究框架已由用户锁定（柱、难点两点、成果归属、总体框架图）。未锁定先走 [研究框架](research-framework.md)。
1. 填表 A、表 B，发现断链先修逻辑。
2. 写章首导语 + 研究背景 + 研究意义，使“研究什么、为何值得做、几种复杂情况”能独立说清。
3. 写研究问题：先定义对象，再各问（图 + 统计 + 两点难点 + 现有不足）。
4. 写研究内容与贡献：框架图、顺承、各条内容（机制打难点）、各条贡献（方法名 + 相对前人）。
5. 写论文组织结构：总述整体难点与各柱；工作章用「提出 A，作用；提出 B，作用；提出 C，作用」，ABC 为后文章内节题，不要复述具体难点。
6. 反向校验：柱名、难点、机制、互为依据句、主线、题目轻呼应从章首追到组织结构。

用户只改某一节：从步骤 1 对表，再只写该节。

## 核心原则

**绪论是全书漏斗：同一套柱名、难点现象词、统计、例子与机制词，从章首走进研究问题，再走进各章与结论。** 好的绪论让读者看清“为何难、问什么、做什么、各章如何排”，并且后文只是展开，不另起一套故事。

研究报告 / 学位论文槽位跟本文件、锁词跟已锁框架与当前稿。成稿把背景与意义分成两个 `\section`，漏斗仍是：研究背景 → 研究意义 → 研究问题 → 研究内容与贡献 → 论文组织结构。柱数与问数、贡献条数与工作章数一致。空白不另开“研究现状”节，缺口写进研究问题各问；谱系留给相关工作章。贡献不报数字。禁止改回旧五节（研究现状与研究空白 / 存在问题与科学问题 / 创新点 / 技术路线）。体裁若无相关工作章，缺口仍写进研究问题，不要把谱系塞进绪论。

## 改定经验（须守）

以下条款来自绪论多轮改定。写或改第 1 章时先按此对表，再动句子。润色、摘要、相关工作、结论若回扣同一套词，不得另起近义。

### 改一词，全书同词

用户改的是锁词本身，不是句模。一次只改锁定短语，绪论、摘要、相关工作、工作章引言、结论同步该词。禁止为读起来更顺、为与范例对称、为各柱工整而换近义。槽位、段内句模仍按本文件；柱数、难点名、互为依据句、主线、应用名仍用当前稿台账。摘要句模见 [摘要](abstract.md)。

失败经验：不要因为柱名叫某任务就把情况名改成该任务动词；不要因为要避开与具体难点撞词就把情况名改成另一套近义。表征与后续任务的关系若已锁为互为依据，不要写回“相互制约”“核心张力”。研究对象不要写成做法。术语一经锁定（如“文档”），不要再译成近义（如“篇章”）。

### 目标、对象、题目只轻呼应

| 锁定项 | 用法 |
|---|---|
| 目标 | 章首第一句、研究问题开篇 |
| 对象 | 章首第一句与研究问题开篇同词；做法是对对象做的事，不要写成研究对象 |
| 封面题目 | 正文不写题目里的“方法研究”四字（若有） |
| 题目两半 | 研究意义节首收一次全称（不含方法研究）；章首用对象句呼应后半；研究问题帽子、研究内容开篇、组织结构收束轻点两半 |

应用 `\item` 禁止再贴“研究面向……技术”。不要把载体（图、序列、超图等）写成研究对象。

### 条件术语分层组句

锁定条件须成对或整组出现，不得拆中心语、不得缩成口号。

| 层 | 允许的组句 |
|---|---|
| 目标 / 问题开篇 / 组织节 / 相关工作收束 | 【条件 A】与【条件 B】条件下；在【条件 A】、【条件 B】的条件下 |
| 研究背景定义句 | 在【条件】下学习 / 完成…… |
| 生活化起笔 | 可用口语化短列，不在此提前甩锁定术语全称 |
| 研究意义 | 可用“往往……，又……”拆开中心语，但锁定词仍在 |

### 难点两套词

| 层 | 用词 | 出现位置 |
|---|---|---|
| 整体难点（情况名） | 台账情况名 | 四种（或 N 种）情况名、各问标题、研究内容条内“针对……情况”、组织节开篇 |
| 具体难点 | 每柱两点 `\textit{}` | 研究问题打开后；“缓解”只用这些原词；工作章引言同词 |
| 成果分打 | 写清谁打 A、谁打 B | 研究内容条内 |

`不考虑` 句用整体难点原词，不要写成“不考虑【具体难点】”。整体难点与具体难点是两套词，不要混成一句。具体难点写成因，不要写成某方法的解法入口。

互为依据句两端以台账为准。研究问题回扣可用“相互支撑”，不要写成“相互制约”。已退役的旧张力句禁止写回。

### 通用载体先出，专用结构后出

先写组织实体关系的通用载体（如图），专用结构（如超图、时序、超边）只在研究问题需要时引入。不要在研究背景 / 研究意义提前写专用结构。研究内容里的方法名若含专用结构，须落在研究问题定义之后。

### 观测须带中心语

指观测到的数据时写“观测数据”（或当前稿锁定的中心语）。首次可写“【形态列举】等观测数据”。不要单独甩“稀疏观测 / 分散观测”。动词“尚未观测到”可留。工作章方法术语不在绪论改。

### 应用锁名，分层组句

每条固定：场景 → 因此/因而需求 → 为此/在此基础上如何支撑。节首点题目两半一次。不写“重要意义”“国家重大需求”。

| 层 | 用词 |
|---|---|
| 章首第二句 | 应用缩写 |
| 背景预告 / 研究意义 `\item` | 应用全称 |

不要为“与研究意义同词”把章首第二句改回长串全称。

### 近义动词不要全书替换

同一现象用同一动词族（如过平滑写“平滑”，域特异被压掉写“抹平”）。不要把所有近义动词统一成一个，也不要为避某词改成另一套而丢掉成稿用词。

### 组织节是章节地图，不是难点复述

不用“用以回应[整体难点] / 缓解 `\textit{难点}`”。工作章与后文 `\section` 对齐：先“本章节针对[柱名]任务进行研究。”再“提出 A，作用；提出 B，作用；提出 C，作用。”ABC 必须是该章技术节标题原词；每个“提出”只两截（方法名 + 一句作用）；各项用中文分号连接，末项句号。作用写方法特点，不要再打具体难点原词。开篇仍用整体难点收各柱。

### 背景与意义分成两个 section

成稿是 `\section{研究背景}`、`\section{研究意义}`，不要再合成一个“研究背景与意义”。

## 七条铁律

1. **漏斗向下，不在绪论展开方法细节。** 背景收到几种复杂情况，研究问题收成各问，再落到各章研究内容。模块、公式、消融留给工作章。
2. **柱名与难点名全书锁死。** 各条线索名 = 研究背景关键任务 = 研究问题所对之章题 = 研究内容条目标题。难点分两层：背景用整体难点；研究问题打开每柱两点具体难点，用 `\textit{}` 锁定。研究内容开篇针对具体难点；条内“针对……情况”回用整体难点；条内“缓解”只用具体难点原词。组织节不复述具体难点。工作章引言、本章小结不得另起近义。
3. **研究问题写缺口，不写本文方法。** 方法名若出现，只属于前人。不要接“为此本文提出”。不要把相关工作章谱系整段搬进来。
4. **每问按下列五步写，不是可检验问句 enumerate。** 该任务旨在 → 如图所示 → 一条已核统计或定性观察 → 现有工作大多……然而……两点 `\textit{}` 难点 → 由于上述两个难点的存在……。不要写“可检验的方向是……（第 X 章）”。
5. **研究内容与贡献分工。** 内容：针对该柱整体难点，写清各项成果如何分打 A 与 B；不报准确率，不写“首个”。贡献：一章一条，方法学新意 + 方法名 + 相对前人；不报数字。一章多项捆进一条。结论按柱收机制，数字以各章主表为准。
6. **研究内容节配总体框架图。** 必须留下；格子、柱名、难点两点、成果名与已锁框架同词。后文各章引言可引用该图。顺承段（谁为谁提供输入）与主线必须同向。图怎么画见 [研究框架](research-framework.md)。
7. **主语用“本文 / 本报告”。** 这是全书层。对应靠同一现象词和同一机制，不靠“回应研究问题一”这类编号。

## 对应链：绪论内与绪论外

### 绪论内部（同一套词走完漏斗）

```text
章首导语（目标 / 对象 / 本章路径）
  → 研究背景（生活化 → 定义 → 落到各柱 → 整体难点）+ 研究意义（若干应用）
    → 研究问题（概念定义 + 各问：标题用整体难点；图 / 统计 / 两点具体难点 / 现有不足）
      → 研究内容与贡献（框架图 + 顺承 + 各条针对整体难点、分打 A 和 B + 贡献不报数字）
        → 论文组织结构（开篇整体难点；工作章提出节题 + 作用，不打具体难点）
```

**柱名锁死示例（学结构，不把示例方法名写入当前稿）：** 事件类别粒度精细 → 细粒度事件检测 → 类别精细难区分 / 类别数据不平衡 → 该方法。当前稿各柱同理，见空白台账。

**统计与例子同族：** 背景 / 研究问题出现的数字与例子，对应工作章必须复用，不另起一套。

**图分层：** 背景概念图可省；研究问题每问一张任务示例图必留；研究内容总框架图必留。

### 绪论外部（后文是展开，不是新故事）

| 绪论锁的东西 | 后文必须对上 |
|---|---|
| 各条线索名 / 各研究问题 | 摘要句5 用中名、分条用短名 + 开展章题全称；相关工作各节标题；各工作章章题。见 [摘要](abstract.md) |
| `\textit{}` 难点现象词 | 摘要总述只用整体难点，条内不写具体难点；工作章引言原词；本章小结“然而…导致”同族。见 [章引言](technical-chapter-intro.md)、[本章小结](technical-chapter-summary.md) |
| 背景 / 问题里的统计与例子 | 对应章引言同一数字、同族例子 |
| 研究内容的机制词 | 摘要“提出一种基于… / 通过…”；章引言工作句；节内术语锁上游。见 [consistency.md](../section/consistency.md) |
| 贡献各条（方法名 + 相对前人，不报数字） | 摘要同样不报数字；结论工作总结与绪论研究内容同词。见 [结论](conclusion.md) |
| 互为依据句与主线 | 摘要不写互为依据句，分条顺序同向主线；结论工作总结首段回扣 |
| 总体框架图 | 各章引言框架定位（可选并入，不另起段） |

## 各节结构

### 章首导语（3 句）

放在 `\chapter{绪论}` 之后、`\section{研究背景}` 之前。

```
本文的研究目标是【锁定条件】下的【目标】，研究对象是【对象】，通过【做法】把【输入】变成【输出】。
【做法】不仅能对【学术侧】起到推动作用，也能为【应用缩写】提供知识支撑。
本章节将首先阐述……背景与意义，然后介绍研究所面临的问题与挑战，最后简要概述研究内容与本文贡献。
```

不在此写方法名、模块或数字。保持三句。第三句用本文件口径（问题与挑战 / 研究内容与贡献），不要写成“空白与科学问题 / 创新点与报告组织”。

### 研究背景、研究意义（两个 `\section`）

#### 研究背景（五层，禁止写“本文提出”）

1. **生活化 / 业务起笔。** 先给场景，不要先点术语名。应用名在此预告时必须与研究意义 `\item` 同词。
2. **“一个很自然的想法便是”→ 应运而生。** 先组织为通用载体，再跨设定融合。加粗定义关键术语。专用结构不要在背景提前出场。
3. **落到各柱。** 用生活例子接到各柱；收互为依据句（若台账有）。禁止写回已退役张力句。
4. **几种复杂情况** `enumerate`，句模如下：

```
\textit{整体难点}，即[两点合说的定义]，使得现实应用[无法做什么]。
不考虑[整体难点]的情况，则难以[任务失败模式]。
```

定义须同时罩住该柱两点具体难点，不要只写第一点。`不考虑` 句用整体难点原词。

5. **收束。** 本文关注【N】个关键任务（各柱全名），分别用来……。

**不要：** 铺学术史；在背景节给方法；把任务书拟开展技术贴进来；用 `[1][2]`。

#### 研究意义

一段“学术 + 应用”，再 `itemize` 若干项。每条固定三拍：场景 → 因此/因而需求 → 为此/在此基础上如何支撑。条目内用段首连词，不要三句并列。不写“国家重大需求”“填补空白”“重要意义”。

封面题目两半在节首收一次。条目禁止再贴「研究面向……技术」。观测带中心语。不要提前写专用结构。

### 研究问题

开篇与章首同对象。再说明通用载体；专用结构只在需要时引入。加粗定义关键概念，必要时配一张三线表对照（表内 `\small`）。回扣互为依据句后进入各问。

标题句模：`\textbf{研究问题N：……情况下的……问题}`。“情况”用已点的整体难点。

**每问内部顺序（不得打乱）：**

1. “该任务旨在……”
2. “如图~\ref{fig:intro-*-task}所示”+ 一句读图（读现象，不读方法模块）
3. 一条已核统计或定性观察
4. “现有工作大多……然而……”→ 锁定的两点 `\textit{}` 难点；必要时用 `\emph{}` 定义关键术语
5. “由于上述两个难点的存在，……”

删掉“可检验的方向是……（第 X 章）”。相关工作章按同一线索展开谱系；此处只为推出难点，不铺文献清单。

### 研究内容与贡献

1. **开篇预告 + 图。** 落到各个研究点。可用 ①–④（或按柱数），各条“针对 `\textit{具体难点 A}` 与 `\textit{具体难点 B}` 问题，提出若干工作”。接总体框架图。
2. **顺承段（句模）。** “第一个研究点……第二个……特别的是……”：按主线写谁为谁提供输入。
3. **研究内容 1–N：**

```
\textbf{研究内容N：[柱名]}
针对[整体难点]情况下的……问题，研究……任务，其主要难点为\textit{A}和\textit{B}。
为此，本文提出……。
[一两句写清各项成果如何分打 A 与 B，不要只并列几个方法名。]
具体而言，……
```

写机制如何打两点难点。不报准确率，不写“首个”，不写模块内部公式。

4. **贡献各条（一章一条）：**

```
\item \textbf{……方面}：提出[方法名]。
      具体来说，……。
      和前人……相比，本文的方法能够……。
```

方法名可用中文 + 简称。不写实验数字。不写“据本文所知 / 首次”，除非相关工作章空白能站住。

### 论文组织结构

先用一段收整体难点与各柱，再按条列。不要写成“第 X 章介绍……”，也不要“用以回应 / 缓解难点”。

```
\textbf{第X章：【章题】。}
本章节对……进行阐述……（相关工作）
或：本章节针对……任务进行研究。
提出[小节标题A]，[一句作用]；提出[小节标题B]，[一句作用]；提出[小节标题C]，[一句作用]。
```

ABC 必须是该章技术节 `\section` 原词。每个“提出”只两截。各项用中文分号连接，末项句号。作用写方法特点，不打具体难点原词。相关工作章用当前稿实际章题。

## 常见问题

### Q：绪论和工作章引言有什么区别？

**绪论**是全书漏斗，背景与意义分成两个 `\section`，主语“本文 / 本报告”，收各柱研究问题与框架图。**章引言**是某工作章 `\section{引言}` 的两段路线图：现实需求 → 两点难点 → 若干项工作。不要把“首先 / 其次 / 最后，提出 xxx”套进研究背景。

### Q：现在还要不要写成一个“研究背景与意义”？还要不要旧五节？

背景与意义分成两个 `\section`。旧五节不要写回去。学的是本文件的段内句模和表述风格；柱数、难点、互为依据句、主线仍用当前稿台账。

### Q：空白写在哪？会不会和相关工作章重复？

缺口写进研究问题各问的“现有工作大多……然而……两点难点”。相关工作章按同一线索写方法谱系，必须新增分类轴或代表机制，不是把研究问题扩写一遍。

### Q：贡献要不要写数字、要不要写“据本文所知首个”？

贡献节不报准确率。数字留给工作章与结论。“首个”仅当相关工作章空白能站住时才写；内容节一律不写“首个”。

### Q：组织节各章一句会不会和相关工作、章引言重复？

组织节是章节地图：针对什么任务，提出哪几个节题、各起什么作用。不要再用“用以回应 / 缓解难点”。

### Q：任务书和技术论文的图都能往绪论里贴吗？

任务书只抽场景与意义，不贴立项技术。图只复用各章**任务示例 / 动机图**；方程对照或结果曲线不要当作研究问题配图。

### Q：审计模式要不要直接改 `.tex`？

**不要。** 审计只报告问题、证据缺口和修改建议。用户同时要求修改时，再按改写执行。
